## CVA Website

The Chippewa Valley Art website is a carry-over project from my last semester of college. For our Software Engineering project, my group decided to create an e-commerce website for the Chippewa Valley Cultural Association (at CVCA’s request). It’s written in PHP using the Laravel framework, and although it’s mostly done, we didn’t quite get to the point of deploying it. I am currently trying to get together a team of programmers to finish the website (I might be able to do it myself, but I can’t seem to self-motivate).

I have also begun working on another website project using Ember.js and Laravel. The goal of the project is to create an application that ‘learns’ your shopping habits (but in a good way!): it’s a shopping list application that will automatically sort your list for you! The project is currently stalled, but I hope to continue working on the idea in the future.

## Online Courses

I am currently taking two Coursera courses: Machine Learning, taught by Andrew Ng (Stanford); and Compilers, taught by Alex Aiken (also Stanford). I am also watching the lectures from Principles of Reactive Programming, taught by Martin Odersky, Erik Meijer, and Roland Kuhn, although the class has already ended.

Stemming from this last course, my interest in functional programming languages has intensified: I am working through the Project Euler problems (projecteuler.net) using Haskell; and, having already gone through “Learn You a Haskell for Great Good!” (learnyouahaskell.com), I am making my way through “Learn You Some Erlang For Great Good!” (learnyousomeerlang.com). In learning Erlang and taking the Reactional Programming course, I have become very interested in the actor model – a model of concurrency that defines various actors that communicate solely through message-passing. I am working on a messaging system, written in Java and Scala, that takes advantage of this model.

## PowerBuilder

The main programming language I use at my job is PowerBuilder, a 4GL and IDE designed around the ‘DataWindow’. Supposedly built with rapid development in mind, PB seems to fight you at every turn! Even the most simple string manipulation becomes a several line statement. And because all code lives in PowerBuilder Libraries (pbl’s) and is partially generated code, traditional source control doesn’t work – if two people edit the same object and try to merge the files, so many things can ‘conflict’ that it’s almost impossible to efficiently merge the files. This restricts our development to person per object!

Although an OO language, most of the PB code in our code-base is directly in the window object (since there are few to no business objects, much of the database interaction is duplicate code). Several of my coworkers and I are currently pushing to switch to a more modern language and I personally am pushing to refresh everyone on basic OO design principles 😛 I have also been very vocal about moving to a more agile development environment (as opposed to the lack of any methodology what-so-ever).

In other words, I’m trying to change everything about the department 😛
